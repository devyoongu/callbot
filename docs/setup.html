1. 시스템 구조 한눈에

Browser (http://localhost:3000)

2. 사전 준비

  • Python 3.11 + 각 서브디렉터리에 venv/ 가 만들어져 있어야 합니다.
  • callbot/.env 가 준비돼 있어야 합니다 (callbot/.env.example 참조).
  • credentials/ (워크스페이스 루트) 에 GCP 서비스 계정 JSON 1개 이상.
  • 사설망 172.31.79.202 (Asterisk), 172.31.79.203 (Qwen3 GPU 서버) 도달 가능한 네트워크.
  • 각 venv 에 의존성 설치: 
    cd callbot && source venv/bin/activate && pip install -r requirements.txt
cd tts-service && source venv/bin/activate && pip install -r requirements.txt
cd web-rtc && source venv/bin/activate && pip install -r requirements.txt

3. 4개 프로세스 기동 절차

순서가 중요합니다 — callbot 이 Asterisk 에 REGISTER 된 뒤에 브라우저가 2001 로 다이얼해야 하고, tts-service 가 떠 있어야 브라우저 타이핑 입력이 동작합니다.

3.1 callbot (SIP 2001)

cd callbot
source venv/bin/activate
python main.py > /tmp/callbot.log 2>&1 &

기동 직후 /tmp/callbot.log 첫 10여 줄에 다음과 비슷한 배너가 보여야 합니다:

AI Callbot Starting
  SIP Server : 172.31.79.202:5060
  Extension  : 2001
  STT        : qwen3-asr (ws://172.31.79.202:30000/api/ws, lang=Korean)
  TTS        : qwen3-tts (http://172.31.79.203:30000, voice=femail_achernar)
  Athena     : configured
Registered as 2001@172.31.79.202. Waiting for calls...

3.2 tts-service (브라우저 타이핑 → 마이크)

cd tts-service
source venv/bin/activate
uvicorn server:app --host 127.0.0.1 --port 8001 &

헬스체크:

curl http://127.0.0.1:8001/health
# {"status":"ok","voice":"chirp3-hd-achernar","language":"ko-KR"}

3.3 web-rtc 이벤트 브리지 (SSE 로 봇 로그 push)

cd web-rtc
source venv/bin/activate
uvicorn server:app --host 127.0.0.1 --port 8000 &

3.4 정적 파일 서버 (브라우저 UI)

cd web-rtc
python -m http.server 3000 &

그리고 브라우저에서 http://localhost:3000 열고 Call 2001 버튼을 누르면 인사말이 들립니다.

4. 정지·재기동

# 전체 정지
pkill -f "python main.py"                          # callbot
pkill -f "uvicorn server:app .* 8001"              # tts-service
pkill -f "uvicorn server:app .* 8000"              # web-rtc 브리지
pkill -f "http.server 3000"                        # 정적 서버

# callbot 만 재기동 (드라이버 변경 후 가장 자주 쓰는 패턴)
pkill -f "python main.py"
cd callbot && source venv/bin/activate && python main.py > /tmp/callbot.log 2>&1 &

5. STT 드라이버 설정

callbot/.env 의 STT_PROVIDER 값으로 전환합니다. 변경 후 callbot 재기동 필요.

값설명필요 환경변수
google Google Cloud Speech-to-Text V2 (default). chirp_3 모델 권장 GCP_PROJECT_ID, GCP_STT_MODEL, GCP_STT_LANGUAGE, CREDENTIALS_DIR
qwen3-asr 원격 GPU 서버의 Qwen3-ASR WebSocket. clientEOS→Final ~150ms (Google sync 대비 ~20×) QWEN_ASR_URL, QWEN_ASR_LANGUAGE, QWEN_ASR_CONTEXT

5.1 Google STT 설정 예

STT_PROVIDER=google
GCP_PROJECT_ID=gen-lang-client-0665942228
GCP_STT_MODEL=chirp_3      # 또는 telephony
GCP_STT_LANGUAGE=ko-KR
CREDENTIALS_DIR=/Users/gimhyeseon/python/ipcc/credentials

5.2 Qwen3-ASR 설정 예

STT_PROVIDER=qwen3-asr
QWEN_ASR_URL=ws://172.31.79.202:30000/api/ws
QWEN_ASR_LANGUAGE=Korean   # 풀네임 (가이드 §7)
QWEN_ASR_CONTEXT=          # 도메인 컨텍스트 (옵션)
드라이버 식별: callbot 기동 배너에 STT : qwen3-asr (...) 또는 STT : google (chirp_3) 가 출력됩니다. 통화 중에는 /tmp/callbot.log 의 [STT] Final (qwen3): ... 또는 STT result: ... 라인으로 확인.

6. TTS 드라이버 설정

callbot/.env 의 TTS_PROVIDER 값으로 전환합니다. 변경 후 callbot 재기동 필요.

값설명필요 환경변수
google Google Cloud Text-to-Speech (default). chirp3-hd-achernar 한국어 여성 음성 GCP_TTS_VOICE, CREDENTIALS_DIR
qwen3-tts 원격 GPU 서버의 Qwen3-TTS HTTP (OpenAI 호환). TTFA 200~350ms QWEN_TTS_URL, QWEN_TTS_VOICE, QWEN_TTS_LANGUAGE

6.1 Google TTS 설정 예

TTS_PROVIDER=google
GCP_TTS_VOICE=chirp3-hd-achernar    # 또는 chirp3-hd-achird (남성)
CREDENTIALS_DIR=/Users/gimhyeseon/python/ipcc/credentials

6.2 Qwen3-TTS 설정 예

TTS_PROVIDER=qwen3-tts
QWEN_TTS_URL=http://172.31.79.203:30000
QWEN_TTS_VOICE=femail_achernar      # 또는 mail_achird (남성)
QWEN_TTS_LANGUAGE=Auto
캐시 분리: 캐시 키가 sha256(text + voice_name) 이라 Google ↔ Qwen3 전환 시 두 캐시가 자동으로 분리됩니다. 충돌하지 않으므로 같은 문장이 다른 음성으로 재생될 우려는 없습니다.

6.3 드라이버 단독 검증

# 서버 헬스
curl http://172.31.79.203:30000/health

# 24kHz PCM 스트리밍 재생 (ffplay 필요)
curl -sN -X POST http://172.31.79.203:30000/v1/audio/speech \
  -H 'Content-Type: application/json' \
  -d '{"voice":"femail_achernar","input":"안녕하세요 테스트입니다","response_format":"pcm","stream":true}' \
  | ffplay -f s16le -ar 24000 -ac 1 -nodisp -autoexit -

# callbot 코드 통해 한 줄 합성
cd callbot && source venv/bin/activate
python -c "from tts_qwen3 import Qwen3TTS; \
           pcm = Qwen3TTS(url='http://172.31.79.203:30000').synthesize('안녕하세요'); \
           print(len(pcm), 'bytes')"

7. 동작 검증 체크리스트

  1. 4개 프로세스 모두 떴는지: ps aux | grep -E "main.py|uvicorn|http.server" | grep -v grep
  2. callbot 배너의 STT/TTS 드라이버 값이 의도와 일치
  3. 브라우저 http://localhost:3000 에서 SIP 상태가 Registered → In Call 순으로 전환
  4. 인사말이 들리고 (TTS), 마이크 또는 타이핑 입력에 대한 응답이 합성·재생
  5. /tmp/callbot.log 에 TTS TTFA: ... (ttfa=NNms), STT result: ... 라인이 흐름
  6. 5턴 자동 검증: 워크스페이스 루트에서 
    source web-rtc/venv/bin/activate
HEADLESS=1 python playwright_call.py

8. 자주 발생하는 문제

증상원인 / 조치
브라우저에서 Call 2001 눌렀는데 통화 안 됨 callbot 이 REGISTER 되지 않은 상태. /tmp/callbot.log 의 Registered as 2001@... 라인 확인. 없으면 Asterisk 도달 가능한 네트워크/방화벽인지, SIP_PASSWORD 일치 확인.
인사말은 들리는데 응답 음성이 안 나옴 TTS 드라이버 측 에러 가능성. grep "TTS synth failed" /tmp/callbot.log. Qwen3-TTS 면 172.31.79.203:30000 도달성 (curl /health) 확인. Google 이면 GCP credential / quota 확인.
마이크/타이핑 입력이 봇에 전달되지 않음 tts-service (:8001) 가 떠 있는지 확인. 브라우저 DevTools Network 탭에서 POST /tts 요청이 200 으로 떨어지는지 확인. CORS 에러면 tts-service/server.py 의 allow_origins 점검.
STT 결과가 자꾸 잘리거나 못 알아들음 Qwen3-ASR: TTS-as-mic 환경에서 일부 발화가 인식 안 될 수 있음. QWEN_ASR_CONTEXT 에 도메인 키워드 넣어보거나 STT_PROVIDER=google + GCP_STT_MODEL=chirp_3 로 전환. Google: 동일 음원에 chirp_3 모델 + adaptation phrase 가 일반적으로 안정.
callbot 종료 안 됨 pkill -f "python main.py". PID 직접 kill 보다 -f <pattern> 방식 권장 (Python 인터프리터 절대경로가 길어서 PID 추적이 번거로움).
